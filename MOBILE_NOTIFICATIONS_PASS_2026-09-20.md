# Уведомления, заявки и чаты — 20.09.2026

Работа по наброску пользователя. Это первый реализованный блок, не закрытие всего списка. Репозиторий prokat, ветка fix/pilot-bugs-and-ui. Backend и web в этом проходе только изучались, схема БД не менялась.

## Сделано

- ChatSocketService ждёт положительный ack `chat:join` и проверяет, что соединение не сменилось. Раньше приложение сразу считало себя участником комнаты, даже при отказе сервера. Неуспешный join не позволяет отправить сообщение; повторная попытка действительно повторяет join. Это исправление подтверждённой ошибки, но конкретный случай с Данияром ещё не воспроизведён.
- Устранено подавление foreground FCM-уведомления лишь потому, что то же событие ранее поступило через сокет. Дедупликация показа отделена от дедупликации данных, повторный FCM не показывает уведомление дважды. Звук/вибрация остаются под контролем существующего системного канала и разрешений устройства; на телефоне не проверены. При отсутствии FCM один сокет пока не воспроизводит звук.
- Поздний push больше не увеличивает счётчик и не делает непрочитанным уведомление, уже загруженное с сервера как прочитанное.
- Колокольчик кратко анимируется при увеличении счётчика; системное отключение анимаций учитывается.
- Уведомления получили локализованную дату/время, сообщения одного чата группируются с последним сообщением; системные события заказов остаются отдельными. Группировка пока по загруженным страницам. Числовой общий счётчик чата намеренно не показывается: для точного значения по всей истории нужен backend. Есть индикатор непрочитанного.
- Тап по группе помечает прочитанными загруженные уведомления группы и открывает чат существующим маршрутизатором. Удаление целой группы не добавлено.
- В заблокированном чате показана иконка замка рядом с существующим локализованным текстом. Логика блокировки и панель отзыва сохранены; регрессионные тесты чатов проходят.
- Исправлена потеря нового REQUEST_CREATED при первоначальной загрузке ленты владельца: после завершения текущего запроса выполняется свежий запрос. Вызовы во время ожидания объединяются; смена пользователя проверяется.

## Что обнаружено в актуальном коде

Backend уже публикует REQUEST_CREATED через workflow:update, а coordinator обновляет загруженную ленту владельца. Инструкции в старом requests/AGENTS.md об отсутствии такого broadcast отстают от кода. Обнаруженная гонка загрузки исправлена, но доставка на двух реальных устройствах ещё не проверена.

У API заявок есть view/cancel/update, но нет отдельного отказа владельца от чужого тендера. Нельзя использовать cancel: это отменит заявку клиента, а пользователь просит скрыть её только для конкретного владельца.

## Осталось из наброска

1. Сохранённое на backend решение владельца по каждой заявке: отклик/скрытие. Счётчик не сбрасывать при входе на экран; учитывать отмену/истечение/выбор исполнителя. Уточнение пользователя о том, убирает ли отклик заявку из счётчика, ещё не получено.
2. Значки +N на разделе заявок, анимация только при первом показе с сохранением просмотренных ID отдельно от решения откликнуться/отклонить.
3. Точный счётчик непрочитанных и последнего сообщения по каждому чату на backend, группировка до пагинации и отметка прочтения всей группы. Сейчас группировка только на клиенте по загруженным уведомлениям.
4. Счётчики/пульсация на кнопках чата в карточке заявки и заказа.
5. Единый показ и звуковой сигнал socket/FCM с соблюдением настроек уведомлений, системного mute/vibration и текущего открытого чата. Сейчас исправлен конкретный конфликт foreground FCM и socket, не вся система оповещений.
6. Два телефона: создание заявки, отклик, первый ответ клиента, ответ владельца, reconnect/background, принятие заказа, завершение и отзыв. Для случая с Данияром нужны chatId/messageId и время события; содержимое личной переписки в логи не выводить.
7. Проверить уведомление о принятии заказа для обеих сторон и его локализованный текст; не считать наличие enum доказательством доставки.
8. Визуальный проход новых элементов на Android/iOS и узком экране, оставшиеся формулировки уведомлений на ru/kk/en.
